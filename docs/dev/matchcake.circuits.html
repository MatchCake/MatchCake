matchcake.circuits.merge_blocks module¶

matchcake.circuits.merge_blocks.merge_blocks(*blocks: Callable[[], Any], wires: Wires | Iterable[Hashable] | Hashable | None = None, contract: bool = False) → List[Operation]¶

Merge circuit blocks acting on disjoint wires into a single circuit.

Each block is a quantum function called without arguments (use a lambda or functools.partial() to bind its parameters and wires). A block may start with its own state preparations (BasisState or ProductState). Since the blocks act on disjoint wires, every state preparation commutes with the gates of the other blocks, so all of them are merged into one ProductState placed first, followed by the gates of every block in order. This is required by the NonInteractingFermionicDevice, which accepts a single state preparation at the start of the circuit.

Wires of blocks without a state preparation start in \(|0\rangle\). The merged operations are queued when called inside a QNode, so the output of the blocks can be used as the input of the next circuit:

@qml.qnode(qml.device("nif.qubit", wires=4))
def circuit():
    merge_blocks(lambda: block_a(params_a, wires=[0, 1]), lambda: block_b(params_b, wires=[2, 3]))
    next_block(params_next, wires=[0, 1, 2, 3])
    return qml.probs(wires=[0, 1, 2, 3])
Parameters:

  • blocks (Callable[[], Any]) – The quantum functions to merge, each called without arguments.

  • wires (Optional[WiresLike]) – Extra wires the merged state preparation must cover, starting in \(|0\rangle\). Defaults to the wires of the blocks only. Only used when a block has a state preparation.

  • contract (bool) – Whether to contract the gates of all the blocks into a single SingleParticleTransitionMatrixOperation.

Returns:

The merged operations: the merged state preparation (if any) followed by the gates.

Return type:

List[Operation]

Raises:

ValueError – If two blocks share a wire, or if a state preparation is not a product state or comes after a gate in its block.

matchcake.circuits.merge_generators module¶

matchcake.circuits.merge_generators.merge_generators(*generators: Iterable[Operation], wires: Wires | Iterable[Hashable] | Hashable | None = None) → Iterator[Operation]¶

Merge generator-based circuits acting on disjoint wires into a single generator of operations.

This is the counterpart of merge_blocks() for circuits given as iterables of operations, such as generators, lists or RandomOperationsGenerator instances. The result is meant for execute_generator() and apply_generator().

A generator may start with its own state preparations (BasisState or ProductState). Since the generators act on disjoint wires, every state preparation commutes with the gates of the other generators, so all of them are merged into one ProductState yielded first, followed by the gates of every generator in order. This is required by the NonInteractingFermionicDevice, which accepts a single state preparation at the start of the circuit.

The merge is lazy: only the leading state preparations of each generator are read before the first operation is yielded, and the gates are then streamed one by one, so a long circuit is never stored in memory. For the same reason, shared wires and state preparations placed after a gate are only detected when the offending operation is reached, and raise a ValueError at that point.

The merged state preparation covers the wires of the state preparations, the wires attribute of the generators that have one (as RandomOperationsGenerator), and the extra wires. Those extra wires start in \(|0\rangle\), like every device wire the merged state preparation does not cover.

Operations are created without being queued, so the merged generator can be consumed inside a QNode with apply().

from matchcake import NIFDevice
from matchcake.circuits import RandomSptmOperationsGenerator, merge_generators

left = RandomSptmOperationsGenerator(wires=[0, 1, 2], seed=0)
right = RandomSptmOperationsGenerator(wires=[3, 4, 5], seed=1)
device = NIFDevice(wires=6)
probs = device.execute_generator(merge_generators(left, right), output_type="probs", reset=True)
Parameters:

  • generators (Iterable[Operation]) – The circuits to merge, each an iterable of operations.

  • wires (Optional[WiresLike]) – Extra wires the merged state preparation must cover, starting in \(|0\rangle\). Only used when a generator has a state preparation.

Returns:

A generator of the merged operations: the merged state preparation (if any) followed by the gates.

Return type:

Iterator[Operation]

Raises:

ValueError – If two generators share a wire, or if a state preparation is not a product state or comes after a gate in its generator.

matchcake.circuits.random_generator module¶

class matchcake.circuits.random_generator.RandomOperationsGenerator(wires: Sequence[int] | int, n_ops: int | None = None, batch_size: int | None = None, op_types: Sequence[Type[Any]] = (), *, use_cuda: bool = False, seed: int | None = None, output_type: str | None = None, observable: Any | None = None, output_wires: Sequence[int] | None = None, initial_state: Sequence[int] | ndarray | None = None, **kwargs: Any)¶

Bases: object

Random circuit of two-wire operations, starting in a random basis state.

Iterating over the generator yields a BasisState on all its wires, followed by n_ops operations. Each operation has a type drawn uniformly from op_types, acts on a random pair of neighbouring wires (w, w + 1) of wires (see neighbouring_wire_pairs()), and has random parameters drawn with the random class method of its type. The same seed gives the same circuit at every iteration, and the generator can be iterated over several times.

The generator is an iterable of operations, so it can be given to execute_generator(), merged with merge_generators(), or used as the body of a QNode with circuit(). The subclasses RandomMatchgateOperationsGenerator and RandomSptmOperationsGenerator set default operation types.

import pennylane as qml

from matchcake import NIFDevice
from matchcake.circuits import RandomMatchgateOperationsGenerator

generator = RandomMatchgateOperationsGenerator(wires=4, n_ops=10, seed=0, output_type="probs")
circuit = qml.QNode(generator.circuit, NIFDevice(wires=4))
probs = circuit()

matchcake.circuits.random_sptm_circuits module¶

class matchcake.circuits.random_sptm_circuits.RandomSptmHaarOperationsGenerator(wires: Sequence[int] | int, n_ops: int | None = None, batch_size: int | None = None, *, use_cuda: bool = False, seed: int | None = None, add_swap_noise: bool = True, initial_state: Sequence[int] | ndarray | None = None, **kwargs: Any)¶

Bases: RandomSptmOperationsGenerator

Brickwork circuit of random rotations approximating a Haar-random free-fermion evolution.

Iterating over the generator yields a BasisState on all its wires, an SptmIdentity on the first pair of neighbouring wires, and then n_ops operations. These operations are blocks of three rotations \(R_{ZZ} R_{YY} R_{ZZ}\) with random angles (SptmCompRzRz, SptmCompRyRy, SptmCompRzRz), placed on the pairs of neighbouring wires (w, w + 1) of wires in turn, in increasing order and starting over after the last pair. With add_swap_noise, a fermionic swap (SptmCompZX) on a random pair of neighbouring wires is added each time the number of operations reaches a multiple of the number of wires. The circuit stops after exactly n_ops operations, even in the middle of a block. The same seed gives the same circuit at every iteration.

from matchcake import NIFDevice
from matchcake.circuits import RandomSptmHaarOperationsGenerator

generator = RandomSptmHaarOperationsGenerator(wires=4, seed=0)
device = NIFDevice(wires=4)
probs = device.execute_generator(generator, output_type="probs", reset=True)

Generate a random circuit of single-particle transition matrix (SPTM) operations.

Each operation has a type drawn uniformly from op_types, acts on a random pair of neighbouring wires (w, w + 1) of wires (see neighbouring_wire_pairs()), and has random parameters drawn with the random class method of its type. No state preparation is yielded: use RandomSptmOperationsGenerator for a circuit that starts with a random basis state.

from matchcake import NIFDevice
from matchcake.circuits import random_sptm_operations_generator

device = NIFDevice(wires=4)
ops = random_sptm_operations_generator(n_ops=10, wires=4, seed=0)
probs = device.execute_generator(ops, output_type="probs", reset=True)
Parameters:

  • n_ops (int) – The number of operations to generate.

  • wires (Union[Sequence[int], int]) – The wires of the circuit, or their number n for the wires 0, ..., n - 1. At least two of them must be neighbours.

  • batch_size (Optional[int]) – The batch size of the parameters of each operation. Unbatched if None.

  • op_types (Sequence[Type[SingleParticleTransitionMatrixOperation]]) – The operation types to draw from.

  • use_cuda (bool) – Whether to move each operation to the GPU.

  • seed (Optional[int]) – The seed of the random generator. The same seed gives the same circuit. Each operation gets its own seed drawn from this generator, so two operations of the same type have different parameters.

  • kwargs – Ignored. Kept for compatibility with the other generators.

Returns:

A generator of the n_ops random operations.

Return type:

Iterator[SingleParticleTransitionMatrixOperation]

Raises:

ValueError – If no two wires of wires are neighbours.
